# Noetix Motion Editor 使用教程

Noetix Motion Editor 用于在 Blender 中导入动作骨架、进行 IK/FK 编辑，并导出干净的
BVH、FBX 或 SMPL-H NPZ 动作。本教程面向正式扩展用户；本地开发版与发布流程请见
[RELEASE_GUIDE.md](RELEASE_GUIDE.md)。

## 1. 开始前

### 支持范围

| 操作 | 支持格式 | 条件 |
|---|---|---|
| 导入 | BVH、FBX、SMPL-H NPZ | 见下方依赖与数据要求 |
| 导出 | BVH、FBX | 必须选中 Noetix 导入后生成的可编辑骨架 |
| 导出 | SMPL-H NPZ | 仅限从 SMPL-H NPZ 导入的骨架 |
| IK/FK | 具备可识别四肢的归一化骨架 | 原始骨架/普通对象不支持 |

### 依赖与本地资源

- **BVH**：Blender 5.2 的内置导入/导出功能，无需单独安装扩展。
- **FBX**：必须安装并启用 **Better FBX Importer & Exporter**。Noetix 不会替你下载第三方插件。
- **SMPL-H NPZ**：需要由你自行取得的标准 SMPL-H 模型目录，目录中必须包含：

  ```text
  smplh/
  ├── male/model.npz
  ├── female/model.npz
  └── neutral/model.npz
  ```

  模型文件受授权约束，不随 Noetix 扩展分发。NPZ 文件中的 `gender` 会决定使用哪一套模型。

打开 Blender 的“偏好设置 → 扩展”，展开 Noetix Motion Editor 后可看到“依赖检测”和
“SMPL-H 本地模型”。依赖显示“正常”后再开始导入；SMPL-H 目录可在此处选择。

## 2. 安装与更新

### 通过扩展仓库安装（推荐）

1. 打开 Blender：**编辑 → 偏好设置 → 获取扩展**。
2. 在“存储库”菜单中添加远程存储库。
3. 填入更新索引地址：

   ```text
   https://raw.githubusercontent.com/momeigui/Noetix-Motion-Editor-Extensions/main/index.json
   ```

4. 刷新扩展列表，搜索 **Noetix Motion Editor**，点击“安装”。
5. 安装后展开条目，确认插件已启用。

### 通过 ZIP 手动安装

从公开发布仓库的 GitHub Releases 下载对应 Windows 安装包，在 Blender 的“获取扩展”中选择
“从磁盘安装”，直接选择 ZIP 文件。**不要解压 ZIP，也不要选择 ZIP 内部文件夹。**

### 更新规则

正式包含 Windows `.pyd` 文件。更新成功后请**完全退出并重启 Blender**，新版本才会被加载。
如果更新或卸载时看到“拒绝访问”，这是 Windows 正在锁定已加载的 Pyd 文件：先关闭 Blender，
再重新打开后更新或卸载。

## 3. 找到面板与认识场景结构

进入 3D 视图，按 `N` 打开右侧栏，选择 **Noetix Motion** 标签。顶部会显示：

- 当前选中的“目标”；没有选择对象时显示“未选择目标”；
- 当前场景“帧率”，可直接调整。调整它会影响时间线播放和后续导出的帧时间。

一次成功导入会产生两类骨架：

| 内容 | 位置 | 用途 |
|---|---|---|
| 源骨架 | `_Noetix_Sources` | 隐藏、不可选中、只读；用来保存原始数据和校验 |
| 归一化 clone | `Noetix_Rigs` | 可见、可选择、可编辑；这是所有 IK/FK 与导出的操作对象 |

日常操作只选择 `Noetix_Rigs` 中的可见 clone。请勿取消隐藏、移动或编辑 `_Noetix_Sources`
中的源骨架，否则动画保真校验与关联维护可能失效。

## 4. 导入动作

建议每次正式导入前使用一个干净场景，避免旧的 `_Noetix_Sources` 与 `Noetix_Rigs` 内容干扰判断。

### 导入 BVH 或 FBX

1. 在“导入”区点击 **导入 FBX/BVH**。
2. 选择 `.bvh` 或 `.fbx` 文件。
3. 等待 Blender 完成导入和动作归一化；长动作的转换会继续在后台进行。
4. 在 `Noetix_Rigs` 中选择新生成的 clone 骨架，检查时间线范围和动作播放。

FBX 会使用 Better FBX 导入器；若没有该依赖，Noetix 会报错而不会静默改用其他导入器。
一个 FBX 含多套骨架时，会为每套骨架创建独立的源骨架与可编辑 clone。没有骨骼的空骨架
会自动剔除；与动作有关的必要 Empty 父级会隐藏保留，以免丢失整体变换。

### 导入 SMPL-H NPZ

1. 先在扩展偏好设置中配置标准 SMPL-H 模型目录。
2. 在“导入”区点击 **导入 SMPL NPZ**，选择动作文件。
3. 插件读取 `poses`、`trans`、`betas`、`gender`、`mocap_framerate`，生成 52 关节骨架。
4. 导入完成后，场景帧率与时间线范围会按 NPZ 的动作数据设置。

此入口只支持 AMASS 风格的 52 关节 SMPL-H NPZ：`poses` 必须是“帧数 × 156”，`trans`
必须是“帧数 × 3”，帧率必须大于 0，且数据不能包含 NaN 或 Inf。普通 NumPy 数据文件不能作为
SMPL 动作导入。

在“维护与校验”区点击 **显示 NPZ 人体**，可按 NPZ 的 `betas` 生成预览人体；它只是预览，
不包含 DMPL 软组织形变。该功能只对 NPZ 导入的 clone 有效。

## 5. IK/FK 编辑

### 创建 IK

1. 选择 `Noetix_Rigs` 中的 clone 骨架。
2. 展开“IK/FK 控制”。如果提示“请选中支持的骨骼”，说明当前对象不是可编辑 clone，或骨架缺少可识别的肢体。
3. 点击 **一键 IK**。
4. 等待控制器和整段动作轨迹烘焙完成；长动作需要更多时间与内存。

创建后会出现 IK 目标、Pole 控制器与内部机械链。默认姿势应保持与导入动作一致；控制器、
机械骨和约束不会进入最终导出文件。

### 切换和编辑

- 面板中的每条肢体都有 **IK** / **FK** 按钮，可无跳变切换。
- 点击 **启动自动 IK/FK** 后，选择 IK/Pole 控制器会自动切到 IK；选择原始肢体骨会自动切到 FK。
- 在 IK 模式下移动末端控制器或 Pole 控制器来编辑动作；手腕、脚腕的最终旋转仍以原动作/骨骼姿势为准。
- 建议正常编辑时保持“自动 IK/FK”开启。关闭它会进入 IK 锁定状态，此时不能直接从面板切回 FK；
若需要继续 FK 编辑，重新开启自动切换后再操作。

### 极向点翻转

如果膝盖或手肘在个别帧发生反向折叠：

1. 选择已创建 IK 的 clone；
2. 在 Pose 模式选中对应 `CTRL.Pole.*` 骨；
3. 打开曲线编辑器，并显示该 Pole 的 XYZ 位置曲线；
4. 在“维护与校验”点击 **修复极向点**。

该工具只清除当前可见 Pole 位置曲线中的异常关键帧，因此操作前请确认选中的是正确 Pole 与曲线。

## 6. 导出动作

所有导出前都要选中 `Noetix_Rigs` 内的可编辑 clone。选中源骨架、控制器之外的对象，或没有选中
对象时，导出会被拒绝。

| 按钮 | 结果 | 注意事项 |
|---|---|---|
| 导出 BVH | 纯骨架 `.bvh` | 骨架对象不可有非均匀缩放，也不可缩放为零 |
| 导出 FBX | 纯骨架 `.fbx` | 需要 Better FBX 已启用 |
| 导出 NPZ（仅支持 NPZ） | SMPL-H 动作 `.npz` | 仅支持由 SMPL-H NPZ 导入的 clone |

导出时插件会逐帧烘焙最终可见姿势到临时骨架；IK 控制器、Pole、机械骨和约束不会出现在
交付文件中。因此无论你最后在 FK 还是 IK 编辑，导出的都是最终动作结果。

### 为什么 BVH/FBX 不能导出为 NPZ？

SMPL-H NPZ 只保存标准 SMPL-H 的关节旋转、根位移和少量元数据，并不保存任意来源骨架的
骨长、骨轴、层级和额外关节。把 BVH/FBX 强行重定向为 NPZ 后无法保证导回完全一致，
所以该路径被明确禁止。若需要 NPZ，请从标准 SMPL-H NPZ 开始导入并导出。

## 7. 检查导入是否保真

1. 选中要检查的 clone。
2. 展开“维护与校验”。
3. 点击 **检测当前骨架动画**。

插件会逐帧比较 clone 与其隐藏源骨架的世界空间位置和旋转，随后在界面与状态栏显示“通过”或
“存在差异”、最大误差、帧范围和骨骼数量。检测耗时与动画帧数和骨骼数成正比；检测期间请等待，
不要播放时间线或编辑骨架。

如果检查失败，先确认没有编辑过源骨架、没有在同一场景混用开发版和正式版；然后重新导入并再次检查。

## 8. 常见问题

### 面板没有出现

- 确认是在 3D 视图中按 `N`，并选择 **Noetix Motion** 标签。
- 在“偏好设置 → 扩展”确认 Noetix Motion Editor 已安装且已启用。
- 本地开发版的标签名是 **Noetix Motion Dev**，不要与正式版混淆。

### FBX 导入或导出失败

检查 Better FBX Importer & Exporter 是否已安装和启用。Noetix 的偏好设置“依赖检测”会显示状态；
安装后重新启用 Noetix，让它自动启用该依赖。

### NPZ 导入失败，提示找不到模型

到扩展偏好设置确认“SMPL-H 模型目录”是否指向包含 `male`、`female`、`neutral` 三个子目录的
父目录；再确认动作 NPZ 的 `gender` 与对应模型文件一致。

### 一键 IK 很慢或 Blender 占用内存高

一键 IK 会对整段动作写入控制器和 Pole 的关键帧。动作越长、骨架越多，耗时和内存越高。
每次仅对一套 clone 执行，避免反复点击“一键 IK”；不需要的骨架和旧场景应单独清理或新建场景。

### 更新、卸载报“拒绝访问”

关闭 Blender 后再操作。这是 Pyd 被 Windows 锁定的已知限制，不是动作文件损坏。

### 导出的文件导回后看起来不对

先确认你导出的是 clone，而不是源骨架；再确认 FBX 依赖正常、BVH 对象没有非均匀缩放。
建议在干净场景重新导入导出文件，并使用“检测当前骨架动画”验证原 clone 与源动作。

## 9. 日常使用建议

- 导入前先保存 `.blend`，复杂动作在副本场景中编辑。
- 不要编辑或删除 `_Noetix_Sources` 中的隐藏源骨架。
- 不要在同一个场景对同一套骨架同时使用开发版和正式版。
- 导出前播放关键片段，确认 IK 编辑结果符合预期。
- 更新正式扩展后总是重启 Blender。
- 需要提交问题时，保留 Blender 版本、插件版本、输入格式、复现步骤和报错截图；不要发送受授权限制的 SMPL-H 模型文件。
